# Слово дано

Личное PWA-приложение для одного пользователя: привычки с расписанием, подтверждение своей фразой,
журнал и push-уведомления. Работает на Cloudflare: Worker со статикой, база D1, Cron Trigger.
Клиент на ванильном JS, без фреймворков. Источник правды по интерфейсу: `reference/slovo-prototype.html`.

## Структура

| Путь | Что это |
| --- | --- |
| `public/` | Клиент: `index.html`, `app.css`, `app.js`, `sw.js`, `manifest.webmanifest`, иконки |
| `public/gate.js` | Вход по `APP_TOKEN`, загрузка модулей, автообновление |
| `public/store.js` | Локальный кеш, оптимистичная запись, офлайн-очередь, экспорт и импорт |
| `public/schedule.js` | Общий модуль расписания: им пользуются и клиент, и сервер |
| `src/worker.js`, `src/api.js` | Worker и API |
| `src/cron.js` | Рассылка push раз в минуту |
| `src/webpush.js` | Web Push (VAPID и шифрование) на WebCrypto |
| `migrations/` | Схема D1 |
| `scripts/gen-vapid.mjs` | Генерация ключей VAPID |
| `scripts/stamp.mjs` | Версия сборки для автообновления |
| `test/` | Автотесты (`npm test`) |
| `android/` | Android-обёртка над PWA для Android Studio, см. `android/README.md` |

## Деплой

Нужны аккаунт Cloudflare, Node.js 20+ и `npm install`.

```bash
npx wrangler login
npx wrangler d1 create slovo-dano
```

Скопируй `database_id` из вывода в `wrangler.toml`. Привязку (`binding`) оставь `DB`, код ждёт это имя.

```bash
npx wrangler d1 migrations apply slovo-dano --remote
node scripts/gen-vapid.mjs
npx wrangler secret put VAPID_PUBLIC_KEY
npx wrangler secret put VAPID_PRIVATE_KEY
npx wrangler secret put VAPID_SUBJECT      # mailto:твой-адрес
npx wrangler secret put APP_TOKEN          # длинный секрет для входа
npx wrangler deploy
```

После деплоя wrangler печатает адрес `https://slovo-dano.<аккаунт>.workers.dev`. HTTPS уже есть, свой домен не нужен.
Приватный ключ VAPID никому не показывай и не коммить. Если сменить ключи, все подписки на устройствах
перестанут работать и push придётся включить заново.

Забытый `APP_TOKEN` восстановить нельзя, но можно задать заново той же командой `secret put`.

### Старый macOS

Локальный режим (`wrangler dev`, `--local`) использует `workerd`, которому нужна свежая macOS.
Если он не запускается, применяй миграции и проверяй приложение на облачной версии (`--remote`).

### Локальная разработка

```bash
npm install
printf 'APP_TOKEN=любой-секрет\n' > .dev.vars        # файл не попадает в git
npx wrangler d1 migrations apply slovo-dano --local
npx wrangler dev
npm test
```

Для проверки push локально добавь в `.dev.vars` ключи VAPID.

## Автообновление

При каждом `wrangler deploy` команда `[build]` из `wrangler.toml` запускает `scripts/stamp.mjs` и пишет
`public/version.json` (хеш файлов). Открытое приложение, в том числе ярлык на домашнем экране, сравнивает
версию с той, с которой загрузилось: при возврате в приложение, появлении сети и раз в 10 минут. Если версия
новая, оно перезагружается само, но только когда ты ничего не делаешь (нет таймера, экрана «Тянет» и ввода).
Service worker берёт файлы сначала из сети, поэтому после деплоя открывается свежая версия, а без сети
открывается из кеша. Ничего вручную делать не нужно.

## Push-уведомления

1. Включи уведомления в настройках приложения (блок «Уведомления на этом устройстве») и нажми «Тестовое уведомление».
2. Cron раз в минуту смотрит расписание в часовом поясе из настройки `tz`. Пояс берётся с устройства
   и меняется вручную в том же блоке.
3. Правила: «Сделать» и «Счёт» напоминают в `remind`, если дело не сделано. «Таймер» напоминает, если
   сегодня не было сессии, и присылает push в конец сессии. «Устоять» шлёт по плотности: тихо (начало и конец),
   обычно (начало, каждые 3 часа, конец), плотно (каждый час). После срыва или подтверждения остаток дня молчит.
4. Каждая отправка пишет ключ `habitId|день|HH:MM|тип` в таблицу `sent`, поэтому повтора не бывает. Cron
   смотрит ещё 4 предыдущие минуты на случай пропуска, но опоздание больше 5 минут уведомление теряет.
5. Подписки, на которые сервис отвечает 404 или 410, удаляются.

### Выбор библиотеки

Пакет `web-push` рассчитан на Node и в Worker может не заработать, поэтому используется собственная
реализация `src/webpush.js` на `crypto.subtle`: VAPID (RFC 8292, JWT ES256) и шифрование aes128gcm
(RFC 8291, RFC 8188). Она проверяется тестами: шифрованный текст расшифровывается независимой
библиотекой `http_ece`, подпись JWT проверяется публичным ключом. `web-push` и `http_ece` стоят только как
dev-зависимости для тестов.

### Ограничения

- **iPhone.** Push работает только у PWA, добавленного на экран «Домой» (iOS и iPadOS 16.4 и новее).
  Разрешение просят только по тапу. Пока приложение не установлено, вместо кнопки показана подсказка.
- **Кнопки в уведомлении** («Тянет») работают на Android Chrome. На iPhone кнопок, по имеющимся данным, нет,
  тап открывает приложение. На практике не проверялось: проверь на своём устройстве и допиши сюда результат.
- Доставка не гарантирована до минуты, режимы «Не беспокоить» и «Фокус» глушат уведомления.
- Push о конце таймера приходит с точностью до минуты, потому что cron запускается раз в минуту.
- Плотный режим быстро надоедает: тексты чередуются, а в настройках есть кнопка перехода на «Обычно».

## Свои тексты уведомлений

В настройках привычки, в блоке «Уведомления», можно задать до 5 формулировок. Подстановки:
`{название}`, `{зачем}`, `{держусь}`, `{осталось}`, `{серия}`, `{прогресс}`. Формулировки чередуются по кругу.
Если своих нет, берутся стандартные. Для «Устоять» они из гайда, для остальных видов написаны по тому же образцу.
Последнее уведомление «Устоять» всегда просит подтвердить фразой. Тексты собираются на сервере и никуда
наружу не отправляются, кроме самого push-сервиса браузера (в зашифрованном виде).

## Глубокие ссылки

`/?habit=ID` выбирает привычку, `/?urge=ID` открывает экран «Тянет». Параметры после обработки убираются из адреса.

## Резервная копия и восстановление

- Экспорт: настройки, блок «Данные», «Экспорт JSON». Файл содержит привычки, весь журнал, тяги и настройки.
- Восстановление: «Импорт JSON» и выбрать файл. Импорт заменяет все данные, поэтому приложение просит
  подтвердить нажатие. Данные возвращаются без потерь (проверено тестом).
- Из командной строки: `GET /api/export` и `POST /api/import` с заголовком `Authorization: Bearer <APP_TOKEN>`.
- Привычки из старого прототипа (localStorage `slovo-dano-v8`) переносятся кнопкой «Перенести привычки с этого устройства».

## Демо

`/?demo=1` включает демо-данные и панель «Демо: подвинуть часы». В этом режиме ничего не пишется на сервер.

## Лимиты бесплатного тарифа

Сверено с документацией Cloudflare (Workers: [limits](https://developers.cloudflare.com/workers/platform/limits/),
D1: [pricing](https://developers.cloudflare.com/d1/platform/pricing/)).
Для одного пользователя расход обычно мал:

- 1440 запусков cron в сутки, плюс обращения самого приложения: заметно меньше 100 000 запросов в сутки.
- D1: за запуск читаются единицы строк (подписки, привычки, журнал за пару дней). Порядка десятков тысяч прочитанных
  строк в сутки при лимите 5 млн, записей порядка десятков при лимите 100 000.
- Тарифные ограничения на запуск cron: 10 мс процессорного времени и 50 подзапросов, включая запросы к D1.
  Это самое тесное место. Тяжёлая часть (подпись и шифрование) выполняется только в минуты с уведомлениями.
  Если в журнале (`npx wrangler tail`) появятся ошибки про превышение лимита CPU или подзапросов,
  уменьши число одновременных напоминаний или переведи Worker на платный план.
- С сентября 2026 бесплатный лимит D1 соблюдается жёстко: запросы сверх него завершаются ошибкой до полуночи UTC.

Точные цифры могут измениться, проверяй их на страницах выше.

## Данные и приватность

Фразы, «Зачем», срывы и тяги личные. Их содержимое не пишется в логи Worker и не уходит во внешние сервисы.
Серверу нужны только привычки, журнал и расписание, чтобы решать, слать ли уведомление.
Журнал на клиенте хранится за последние 60 дней (так отдаёт `/api/state`), в экспорте он полный.
